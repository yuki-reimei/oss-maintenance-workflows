# Release Checklist

Use this checklist before publishing a small project release.

## Before release

- Review merged changes since the last release.
- Check open issues for known regressions.
- Confirm README instructions are still accurate.
- Update changelog or release notes.
- Confirm license and attribution files are present.
- Run available tests or manual verification steps.

## Release notes

Release notes should include:

- Summary of user-visible changes
- Bug fixes
- Documentation updates
- Known limitations
- Upgrade or migration notes, if needed

## After release

- Publish the release notes.
- Check support channels for reports.
- Open follow-up issues for deferred work.
- Archive release-specific notes if useful.
