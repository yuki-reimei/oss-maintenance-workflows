# Issue Triage Workflow

This workflow is designed for small public projects where maintainers need a repeatable way to handle user reports.

## Goals

- Understand the report quickly
- Identify whether it is a bug, support request, feature request, or documentation issue
- Ask for missing reproduction details early
- Keep public responses clear and respectful

## Steps

1. Read the report and identify the main request.
2. Add one classification label.
3. Check whether the report includes version, environment, expected behavior, and actual behavior.
4. Ask for missing details with a short response.
5. Link related issues if they exist.
6. Decide whether the next action is documentation, code change, investigation, or closure.

## Suggested labels

- `bug`
- `documentation`
- `enhancement`
- `question`
- `needs-info`
- `maintenance`

## AI-assisted use

AI tools may be used to summarize long reports, draft response text, or identify missing reproduction details. Maintainers should review responses before posting.
